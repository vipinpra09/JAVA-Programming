
🔹 Method Overloading
What it is:
Same method name, different parameter list, in the same class (or inheritance doesn’t matter).

Decided at: Compile time
👉 So it’s called compile-time polymorphism

Example:

class MathOp {
    void add(int a, int b) {
        System.out.println(a + b);
    }

    void add(int a, int b, int c) {
        System.out.println(a + b + c);
    }
}
✔ Same method name: add
✔ Different parameters
✔ No inheritance required

🔹 Polymorphism
What it is:
One thing, many forms.

In Java, polymorphism mainly happens through:

Method Overloading (compile-time)

Method Overriding (runtime)

So 👉 method overloading is a TYPE of polymorphism, not the same thing.

🔹 Method Overriding (Runtime Polymorphism)
This is the most important polymorphism concept in Java.

Requirements:

Inheritance

Same method name

Same parameters

Different implementation

Decided at: Runtime

Example:

class Car {
    void sound() {
        System.out.println("Car sound");
    }
}

class Honda extends Car {
    @Override
    void sound() {
        System.out.println("Honda sound");
    }
}

class Test {
    public static void main(String[] args) {
        Car c = new Honda();
        c.sound();  // Honda sound
    }
}
✔ Reference type = Car
✔ Object type = Honda
✔ Method called at runtime → polymorphism

🧠 Final Comparison (Easy to Remember)
Concept	Same Thing?	When Decided	Inheritance Needed
Method Overloading	❌ No	Compile time	❌ No
Polymorphism	✅ Yes (concept)	Compile/Runtime	Sometimes
Method Overriding	✅ Yes (type of polymorphism)	Runtime	✅ Yes
📌 Key takeaway
Method overloading ≠ polymorphism
Method overloading = compile-time polymorphism

✅ Method Overloading Example
class Calculator {

    // method with 2 parameters
    void add(int a, int b) {
        System.out.println(a + b);
    }

    // method with 3 parameters
    void add(int a, int b, int c) {
        System.out.println(a + b + c);
    }

    // method with different data types
    void add(double a, double b) {
        System.out.println(a + b);
    }

    public static void main(String[] args) {
        Calculator c = new Calculator();

        c.add(10, 20);        // calls add(int, int)
        c.add(10, 20, 30);    // calls add(int, int, int)
        c.add(5.5, 4.5);      // calls add(double, double)
    }
}
🔹 Why this is method overloading?
✔ Same method name → add
✔ Different parameter list (number or type)
✔ Happens in the same class
✔ No inheritance needed
✔ Resolved at compile time

❌ Not Method Overloading
void add(int a, int b) { }
int add(int a, int b) { }  // ❌ ERROR (only return type changed)
Changing only the return type is not overloading.

🧠 One-line exam answer
Method overloading is defining multiple methods with the same name but different parameters in the same class.

✅ Method Overriding Example
class Car {
    void run() {
        System.out.println("Car is running");
    }
}

class Honda extends Car {
    @Override
    void run() {
        System.out.println("Honda is running");
    }
}

class Test {
    public static void main(String[] args) {
        Car c = new Honda();   // parent reference, child object
        c.run();              // calls Honda's run()
    }
}
🔹 Why this is method overriding?
✔ Inheritance is required (extends)
✔ Same method name → run()
✔ Same parameters
✔ Same return type
✔ Method is redefined in child class
✔ Resolved at runtime → runtime polymorphism

🧠 Key Rules to Remember
Method name must be same

Parameter list must be same

Inheritance is mandatory

Access level in child must be same or wider

@Override is optional but recommended

🔄 Overloading vs Overriding (Quick Comparison)
Feature	Overloading	Overriding
Class	Same class	Parent–child
Parameters	Different	Same
Inheritance	Not required	Required
Polymorphism	Compile-time	Runtime
✨ One-line exam answer
Method overriding is redefining a parent class method in the child class with the same signature.

✅ Polymorphism (Java Example)
Meaning:

One object, many forms.

In Java, polymorphism mainly happens through method overriding.

🔹 Runtime Polymorphism Example
class Animal {
    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

class Test {
    public static void main(String[] args) {
        Animal a;

        a = new Dog();
        a.sound();   // Dog barks

        a = new Cat();
        a.sound();   // Cat meows
    }
}
🔹 Why this is polymorphism?
✔ Same reference type (Animal)
✔ Different object types (Dog, Cat)
✔ Same method call → sound()
✔ Different behavior at runtime

That’s runtime polymorphism.

🔹 Types of Polymorphism in Java
Compile-time Polymorphism

Method Overloading

Runtime Polymorphism

Method Overriding

🧠 One-line exam answer
Polymorphism is the ability of an object to take many forms, achieved using method overloading and overriding.

🔄 Relation Between Concepts (Super Important)
Overloading → Compile-time polymorphism

Overriding → Runtime polymorphism

Inheritance → Required for runtime polymorphism
